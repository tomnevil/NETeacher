# 协作与变更管理

> 文档与后续工程的协作规范。本期为文档交付，规范同样适用于文档评审与后续开发。

## 1. 分支与版本模型（Git）
- `main`：稳定基线（文档评审通过合入）。
- `docs/<topic>` 或 `feature/<req-id>`：变更分支。
- 提交信息：`[FR-ACC-002] 补家长绑定异常分支` 或 `[DOC] 修正 SOE 勘误`。
- 合入 `main` 需 PR + 至少 1 人评审。

## 2. CI/CD（工程阶段参考）
- CI：Lint + 单测 + SAST + 接口契约校验（OpenAPI/Swagger 与 `API接口规范.md` 对齐）。
- CD：M1 用 Docker Compose；M2 起 K8s；灰度 10%→50%→100%。

## 3. 环境
| 环境 | 用途 |
| --- | --- |
| Dev | 开发联调 |
| Test | QA/性能/合规 |
| Staging | 灰度前验收 |
| Prod | 生产（可用性≥99.9%） |

## 4. 需求变更流程
1. 提出：Issue 关联需求编号（如 `FR-LRN-007`）。
2. 影响评估：范围/工作量/风险（引用 `风险登记册.md`）。
3. 评审：PM+研发+QA 评审，重大变更更新 `PRD-主文档.md` 需求总表与版本记录。
4. 实施与回归：更新相关文档/接口/数据字典，跑 `质量与测试策略.md` DoD。

## 5. 文档一致性维护
- 新增术语同步登记 `README.md` 术语表。
- 修改 FR 编号需同步更新主文档需求总表与相关子文档。
- 接口/数据字段变更需同步 `API接口规范.md` 与 `数据字典.md`。
- 每里程碑做一次全量交叉审校：编号、术语、数据表字段、接口路径三者对齐。
