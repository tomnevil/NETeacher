# 技术选型对比与决策

> 给出 3 套方案对比矩阵与推荐结论。基线为 `reference/PLAN.md` 原方案，结合用户决策「Web 优先 + H5 适配」「需要对比建议」修订。
> 本文档结论被 `系统架构设计.md`、`API接口规范.md`、`数据字典.md`、`非功能需求与性能指标.md` 引用。

## 0. 总体原则
- **渐进式架构**：按 M1 模块化单体 → M2 加消息队列/异步 → M3 视规模评估微服务拆分。
- **云厂商能力优先**：AI 评测/语音先用腾讯云托管能力，避免过早自研重投入。
- **Web 优先**：前端一套 React 代码覆盖桌面与 H5，原生 App 非本期。

## 1. 前端（Web 优先 + H5 适配）

| 维度 | A（推荐）React 18+TS+Vite+Tailwind+shadcn/ui+Zustand+TanStack Query+ECharts | B Vue3+Vite+Vant/Element Plus | C Next.js(SSR) |
| --- | --- | --- | --- |
| 组件生态 | 成熟、社区大 | 国内 H5 生态好 | 全栈一体 |
| 多端覆盖 | 同一套代码+响应式断点 | 需维护两套组件库风格 | 桌面强、H5 一般 |
| SEO | 弱（应用内无需） | 弱 | 强（营销站利） |
| 学习成本 | 中 | 低 | 中高 |
| 结论 | **采用** | 备选 | 仅营销官网单独使用 |

**推荐 A**：最契合「Web 优先兼顾 H5」。若后续需营销官网/落地页 SEO，再用 Next.js 单独建站，二者不冲突。

## 2. 后端服务

| 维度 | A Spring Cloud 微服务（PLAN 原案） | B（推荐）Spring Boot 3 模块化单体 | C 腾讯云 CloudBase Serverless |
| --- | --- | --- | --- |
| 运维成本 | 高（多服务/注册中心/链路） | 低（单进程多模块） | 最低 |
| 团队<10人适配 | 差 | 好 | 好 |
| 长耗时任务(口语评测) | 适配 | 适配（异步线程/队列） | 受冷启动/时长限制，不适合正式 |
| 未来拆分缝 | 天然 | 预留模块边界 | 弱 |
| 结论 | 规模化再用 | **采用（M1 单体多模块）** | 仅演示/POC |

**推荐结论**：M1/M2 采用方案 B 的简化形态（单进程多模块：用户/课程/学习/评测/推荐/运营/订单），通过 Spring Cloud Gateway 统一入口，预留微服务拆分边界；P2 引入消息队列与异步任务；P3 视规模评估按模块拆分微服务。
**替代选项**：若团队以 TypeScript 为主，后端改用 **NestJS** 以统一前后端语言（模块边界同构）。

## 3. AI 能力层

| 能力 | 推荐 | 备选 | 说明 |
| --- | --- | --- | --- |
| 口语评测 | 腾讯云**智聆口语评测 SOE**（音素级） | 科大讯飞、阿里云 | **PLAN「慧眼」为人脸核身，勘误为 SOE** |
| 语音识别 ASR | 腾讯云 ASR（实时/一句话） | 同上 | 用于对话训练语音输入 |
| 语音合成 TTS | 腾讯云 TTS（童声/外教音色） | 同上 | 标准发音示范 |
| 语言理解/对话/纠错 | 混元大模型 或 自部署 Qwen 系列 | GPT 类（合规风险） | 对话训练、语法纠错、作文批改 |
| 自研发音评测模型 | P3 评估 | — | 前期「云 SOE + 业务规则后处理」 |
